# RDQ 需求規格：公務車藍牙定位追蹤系統

## 一句話任務
在既有臺北農產巡檢平台新增獨立的「SYS-13 公務車定位追蹤系統」，以 Android／iPhone App 綁定車上 BLE 標籤，使用手機 GPS 與行動網路回傳位置，並在繁體中文管理端提供即時地圖、歷史軌跡、電子圍籬、告警及權限管理。

## ✅ 已確認
- 追蹤對象：公務車輛，第一階段公司內部使用，規模 50 台以內。
- 手機平台：Android 與 iPhone 同步開發，不採只有網頁的背景定位方案。
- 背景定位：車輛移動時目標每 30～60 秒回報；停止時降低頻率，恢復移動時自動加快。
- 網路處理：手機有 4G／5G 或 Wi-Fi 時即時上傳；離線時本機暫存，恢復連線後依時間順序補傳。
- 第一版功能全部納入：即時地圖、最後位置、在線狀態、歷史軌跡、停留點、里程統計、電子圍籬、離線／逾時告警、設備綁定／解除綁定及權限管理。
- 地圖採零成本優先：使用 MapLibre 開源地圖引擎，不綁定 Google Maps；圖磚來源必須可以由後台設定或環境設定切換。
- 定位資料保存：原始定位點 90 天；每日軌跡與里程摘要 1 年；啟用中車輛的最後位置持續保留。
- 介面文字、狀態、錯誤及告警全部使用繁體中文。
- 定位追蹤必須是入口頁上的獨立大系統，不掛在 SYS-07 公務車派車管理底下；使用獨立 `sys_vehicletracking` 存取權限，但引用同一份公務車主檔。
- 使用者提供的 FindTag 畫面僅作功能與操作流程參考，不照抄品牌、圖示、地圖樣式或版面。

## ❓ 假設（未確認，已採預設值，隨時可推翻）
- 正反面與電池艙照片顯示裝置採鈕扣電池供電、外殼無可見 SIM 卡槽或 GPS／4G 型號標示，因此暫定為低功耗藍牙標籤，不假設它具備 GPS、SIM 卡或自行上網能力；定位來源為已綁定手機的 GPS。照片仍不足以確認其藍牙協定與可讀取識別資料。
- 因目前沒有品牌、型號、包裝或 BLE 通訊文件，暫定硬體會廣播一個可被 iOS／Android 穩定讀取的識別資訊；此假設必須先由實機可行性測試驗證。
- App 採 React Native 搭配必要的 iOS／Android 原生背景服務；管理端沿用既有 V2 網站與 Supabase 帳號、角色及稽核機制。
- 每個 BLE 標籤同一時間只能綁定一台公務車；每台車可更換標籤，但必須保留綁定歷程。
- 即時狀態預設：最後定位 3 分鐘內為「在線」、超過 3 分鐘為「未更新」、藍牙中斷為「標籤未連線」。門檻由後台設定。
- 告警預設使用 App 推播與系統內通知；簡訊、LINE 或電子郵件不列為第一版必要條件。
- 圖磚策略：開發／驗證環境可使用符合條款的免費方案；正式環境優先自架臺灣範圍的向量圖磚或使用具免費額度的服務。不得把 OpenStreetMap 公共圖磚當作有 SLA 的正式依賴，也不得批次下載其公共圖磚。
- 定位僅在使用者明確開始勤務／行程且授權後執行，結束勤務後停止背景追蹤；保留存取與設定異動稽核。
- 地圖操作暫定包含標籤／車輛搜尋、最新資料、最近 1／2／4／6 小時、最近 1 天與自訂起訖時間篩選、重新整理、回到目前位置、歷史日期選擇及車輛清單。
- 多車或多定位點必須使用群聚、軌跡抽稀與標籤防重疊；地圖上不直接堆疊大量日期文字，點選定位點後才在資訊卡顯示時間、地址、速度、精度及狀態。
- 參考畫面中的「尋鈴／發聲」功能僅在實機驗證確認 BLE 標籤具有可寫入的響鈴特徵值後開啟；否則隱藏該操作，不顯示無效按鈕。

## ➕ 已採納（象限Ⅳ）
- 可替換的 BLE 設備介接層：硬體識別、掃描、連線與資料解析不寫死在畫面或業務流程中。
- 智慧定位頻率：移動時 30～60 秒，靜止時降頻，以兼顧即時性與手機電量。
- 定位資料分層保存：原始點 90 天、彙總 1 年、最後位置隨車輛啟用狀態保留。
- 地圖費用保護：MapLibre 為預設引擎、圖磚來源可切換、設定流量監控及上限。
- 隱私與稽核：顯示定位中的狀態、限制非勤務追蹤、記錄查詢、匯出、綁定及設定異動。

## ❌ 排除項（明確不做）
- 第一版不使用 Google Maps 付費服務；未來如有街景、路況或 Google 導航需求，再以可切換介面加入。
- 不承諾手機不在車上、藍牙關閉、定位權限被撤回或手機完全關機時仍能追蹤；若需要此能力，必須改用內建 GPS＋SIM／eSIM 的車載定位器。
- 不仿製 Apple「尋找」或 Google 群眾協尋網路，也不使用未經授權的私有協定。
- 不包含硬體設計、韌體修改、SIM 資費與行動裝置管理系統建置。
- 不在硬體可行性驗證前承諾照片中的未知標籤一定能由自建 App 綁定。

## 📋 一段式需求規格
在既有臺北農產 V2 平台新增入口頁獨立大系統「SYS-13 公務車定位追蹤系統」，使用獨立 `sys_vehicletracking` 權限並引用 SYS-07 既有公務車主檔，服務公司內部 50 台以內公務車。系統下設即時車況、歷史軌跡、藍牙設備、電子圍籬及定位告警五個子系統。每台車配置一枚 BLE 標籤，Android 與 iPhone App 可掃描、辨識、綁定及解除綁定，並在勤務期間使用手機 GPS 回傳位置；車輛移動時以 30～60 秒為目標頻率，靜止時自動降頻，網路中斷時加密暫存在手機並於恢復連線後補傳。後台以 MapLibre 呈現繁體中文地圖，支援第一／最後位置、在線狀態、車輛聚合、歷史軌跡播放、日期篩選、停留點、里程統計、電子圍籬，以及離線、長時間未更新與藍牙中斷告警。地圖圖磚來源不得寫死，測試期使用符合條款的免費來源，正式期優先採自架臺灣向量圖磚或具免費額度且可替換的供應商。資料沿用既有 Supabase 架構並套用 RLS、角色權限及稽核；原始定位點保存 90 天，每日軌跡與里程彙總保存 1 年，啟用中車輛的最後位置持續保留。第一個開發閘門是未知 BLE 標籤的實機可行性驗證：取得廣播名稱、裝置識別、服務 UUID、特徵值及 iOS／Android 背景可見性；若標籤無法穩定被自建 App 辨識，必須先更換成有公開協定的 BLE Beacon／車載定位器，再進入正式功能開發。

## 🧭 建置階段
1. **硬體可行性驗證**：建立 BLE 掃描測試 App，盤點廣播資料、UUID、可讀寫特徵、電池資訊與背景喚醒能力；Android／iPhone 都通過才放行。
2. **定位最小可行版本**：完成登入、車輛／標籤綁定、勤務開始／結束、背景定位、離線補傳及即時地圖。
3. **營運功能**：加入歷史軌跡、停留點、里程、電子圍籬、告警、角色權限及稽核。
4. **試營運與調校**：以少量公務車進行耗電、漏點、重複點、定位漂移與弱網測試，據結果調整頻率及門檻，再擴到 50 台。

## ✔ 驗收條件
- [ ] Android 與 iPhone 均能掃描並顯示目標標籤，完成唯一綁定、解除綁定及重新綁定；重複綁定會被阻擋並顯示繁體中文原因。
- [ ] App 取得必要權限後，勤務期間在螢幕關閉及 App 退到背景時仍能持續收集位置；移動期間相鄰有效點的目標間隔為 30～60 秒。
- [ ] 無網路時定位點不遺失，恢復網路後可依原始時間補傳，伺服器會去除重複點並拒絕不合理時間或座標。
- [ ] 後台地圖可切換全部／單台車，顯示最後位置、更新時間、速度、方向、定位精度、藍牙狀態及在線狀態。
- [ ] 地圖提供車輛搜尋、最新／1／2／4／6 小時／1 天／自訂區間篩選、目前位置、重新整理及車輛清單；大量定位點不互相遮蔽，點選後才顯示完整明細。
- [ ] 可依車輛與日期下鑽查詢並播放歷史軌跡，顯示停留點、里程與資料缺口；所有欄位及狀態為繁體中文。
- [ ] 管理者可建立圍籬及告警規則；進入、離開、逾時未更新與藍牙中斷會產生通知並保留處理紀錄。
- [ ] 角色至少分為系統管理員、車輛管理員、調度／查詢人員及駕駛；未授權者無法查詢、匯出或變更定位資料。
- [ ] 原始定位點依 90 天規則處理，每日摘要保留 1 年；保留政策、匯出、查詢、綁定與設定異動均可稽核。
- [ ] MapLibre 在 Android、iPhone 與網頁管理端正常顯示，圖磚供應來源可切換，切換時不需重寫定位與業務功能。
- [ ] 完成 Android／iPhone 實機耗電與背景穩定性報告；若任一平台受作業系統限制而未達 30～60 秒，報告須列出實測間隔與替代策略，不得以推測宣稱通過。

## ⚠ 開工前必要條件
- 提供設備背面／電池蓋內照片，或讓工程端以 Android 與 iPhone 實機掃描該裝置。
- 可建立 iOS 測試 App 的 Apple Developer 簽署條件，以及 Android 測試安裝條件。
- 確認現有 Supabase 測試環境可新增定位相關資料表、Edge Function／排程及 RLS。
