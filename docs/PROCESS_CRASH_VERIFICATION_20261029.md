# 2026-10-29 儲存程序強制中斷補驗

## 新增的驗證範圍

基於分支 59044c1d144c146295f2390753c572313957549b，將原列於實機限制的「突然中斷」拆開：**程序被終止可先隔離驗證，真實斷電／原生資料庫／跨執行個體仍不能代替**。本輪新增持續回歸測試，沒有修改產品執行程式、儲存格式、金鑰名稱、保留政策、依賴版本或密碼政策。

測試載入實際 encrypted-storage.ts；AsyncStorage 與 SecureStore 以專屬暫存目錄的檔案介面替代，使用 Node AES-256-GCM 實作加解密介面。每次儲存介面操作以寫入暫存檔再 rename 發布，假定單一已完成操作具原子性；這不是原生 SQLite／Keystore 的實作。不同測試階段由不同 OS 子程序執行，不共用 JavaScript 記憶體、鎖或快取金鑰。

寫入到指定階段後，子程序透過 IPC 回報並停住；父程序強制終止該子程序，確認沒有正常完成結果，再啟動全新程序讀回。中斷點沒有執行產品 catch／finally 補救。只傳輸雜湊與狀態，不輸出明文內容或金鑰。測試完成後，驗證暫存目錄仍位於指定根目錄內才清理；不接觸專案或正式資料。

## 六項結果

| 中斷位置 | 全新程序讀回結果 |
|---|---|
| 大筆新密文的分段寫入途中 | 舊索引仍有效，讀到完整舊值，沒有讀到部分新資料 |
| 完整新分段索引已發布、舊分段清理尚未完成 | 讀到完整新值，不倒退到舊值 |
| 大筆資料改為短密文，短值已發布 | 讀到新短值，不回退至舊分段 |
| 舊明文遷移已發布密文，尚未刪明文 | 新程序驗證密文成功後繼續移除舊明文，讀回完整原值 |
| 登出紀錄已由單一原子移除操作刪除 | 新程序讀回 null，紀錄不復活；不把此項當成原生 multiRemove 原子性證明 |
| 儲存金鑰已保存，第一筆密文尚未寫入 | 新程序沿用已保存金鑰，後續加解密成功，不另生成覆蓋該金鑰 |

本機新測試 **6/6 pass**。新增 storage-crash.test.cjs 與 fixtures/storage-crash-worker.cjs，接入既有 test:storage，完整集合由 60 增為 66 項；最終 CI 的整組數量與結果以推送後同 SHA 回讀為準。新增兩個測試檔的 Semgrep 3 條規則掃描通過、0 findings。未把既有實機或原生模擬器結果算成本輪新增證據。

## 仍存在的密文殘留限制

測試明確確認兩種中斷會留下**未被現行索引引用的密文分段**：未發布的新分段，以及已切換新索引但尚未清掉的舊分段。它們不影響本輪讀回正確性，但可能占用空間，不能聲稱全數遵守邏輯佇列的清除時點、完成實體抹除或無限次中斷仍不占空間。

這是 [先前故障報告](ISOLATED_FAULT_VERIFICATION_20261029.md) 已保留的清理／跨執行個體限制，本輪補上程序中斷反例。**尚未修正自動回收**：目前鎖只在單一 JavaScript 執行個體內，另一個原生執行個體可能仍在準備尚未發布的分段；只根據「目前沒有索引引用」掃描刪除，可能誤刪仍在寫入的資料。安全的自動回收需先具備跨執行個體協調或原生交易機制，不能直接加入不具同步保證的刪除程式。

目前控制為：內容保持 AES-GCM 加密；分段全數寫完才發布索引；讀取驗證不通過即回報錯誤；正常寫入／登出保留既有清理；空間不足仍回報失敗，既有原生 SQLite_FULL 證據另見 [儲存補驗](NATIVE_STORAGE_CLOSEOUT_20261029.md)。不擅自刪除無法證明安全的分段，殘留回收限制保持未結案。

## 隔離邊界及最少配合

本輪未啟動模擬器、沒有 Supabase 寫入、沒有外部通知或正式連線。未量測硬體 flush／fsync、突然斷電、SQLite 損壞、Android／iOS 原生金鑰儲存、跨原生執行個體同時寫入、射頻或耗電。真實設備仍需下列最少條件：

| iOS 原生 | 提供 Mac／Xcode、連接並信任 iPhone，由本人完成必要簽章授權 |
| 正式 IIS／VPN／代理／Python | 完成 VPN／MFA，提供指定站台與主機唯讀連線 |
| 外部通知 | 指定測試帳號／收件人並授權單次發送，由本人完成必要 OAuth／MFA |
| 異機復原 | 提供空白隔離第二主機、核准去識別備份及安全金鑰取得管道，指定 RPO／RTO |
