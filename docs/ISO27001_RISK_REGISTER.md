# 巡檢系統 ISO/IEC 27001 風險與控制工作底稿

更新：2026-10-24。這是供風險所有人審核的**草稿**，不是已核准的風險評估或完整 SoA。
納管邊界暫定為網站、Supabase／Node API、行動追蹤程式、訊號服務、CI／發布、備份與自架主機；組織、場所、委外責任及資料所有人待正式核定。

## 評估方法與責任

- 資產：巡檢與派車紀錄、帳號與權限、位置資料、稽核與備份、發布憑證、主機及網路設定。
- 影響及可能性各採 1（低）至 5（高），初始分數為兩者相乘。1–5 低、6–12 中、15–25 高；缺證據時不得自行降低分數。
- 每項須由組織指定風險所有人、確認現況、措施期限與剩餘風險；超過接受標準須核准處理，不得由程式提交取代簽核。
- 證據狀態依序區分「已發現／程式已修正／隔離測試通過／正式環境驗證／權責人結案」。沒有證據的格子維持待辦。

## SoA 候選控制與證據入口

以下僅為**候選對應**，不是 93 項 Annex A 完整適用性聲明。每一項的適用／排除理由、實施程度與責任人須由正式風險評估決定。

| 控制 | 候選理由 | 現有技術證據 | 尚需組織／正式環境證據 |
|---|---|---|---|
| A.5.9 資產清冊 | 網站、設備、帳號、資料及雲端服務需定義所有人 | 本表暫定資產類別 | 核定清冊與所有人 |
| A.5.15、A.5.16、A.5.17、A.5.18 存取、身分及驗證資訊 | 帳號核准與撤權、密碼、行動登入 | 帳號啟用流程、權限測試、加密儲存 | Auth 設定、MFA、權限複核與停權證據 |
| A.5.23 雲端服務安全 | Supabase、GitHub、Expo 及供應商 | 部署 gate、相依清單 | 契約、共擔責任、服務設定核定 |
| A.5.24–5.28 事件管理 | 告警、分級、蒐證與應變 | security-monitor、事件紀錄 | 通報演練、鑑識與改善結案 |
| A.5.29、A.5.30 中斷期間與 ICT 復原 | 需證實核心服務可恢復 | 備份程序與既有加密備份 | 隔離環境完整恢復及 RTO／RPO 量測 |
| A.8.8、A.8.9 弱點與設定管理 | 相依公告及代理／CSP 設定 | 掃描、主分支檢查、CSP 產物 | node-forge 處理、正式主機設定讀回 |
| A.8.12、A.8.24 資料外洩防護及密碼學 | 權杖與位置資料須受保護 | 行動儲存密文化與保存期限 | 實體裝置、金鑰生命週期與遺失處理 |
| A.8.15、A.8.16 日誌與監測 | 限流及異常偵測需可信來源 | 共用 IP 正規化、監測程式 | 代理信任邊界測試、告警演練及留存檢查 |
| A.8.25–8.29 安全開發與測試 | 變更與上線前檢查 | PR 必要檢查、部署 gate、建置測試 | 獨立審查、定期測試範圍與發現追蹤 |

後續需補全標準條款 4–10 的範圍、政策、能力、績效及改善證據；安排客觀內部稽核與管理審查。不得把本底稿或 CI 成功表述為 ISO/IEC 27001 認證。
