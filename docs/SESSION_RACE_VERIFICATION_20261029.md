# 2026-10-29 勤務查詢與本機操作交錯補驗

## 問題與修正

本輪以修正分支 537a9a3b618c99f8002933f21fbff9731411ab23 為基準，補驗前輪「伺服器勤務狀態核對」與本機開始／結束操作同時進行的情況。前輪已驗證不同帳號刷新之間的延遲回應，但沒有涵蓋**同一帳號內，本機勤務已改變、舊查詢仍在途**的時序。

受控 Promise 延遲測試在舊碼重現三個失敗：

| 舊回應抵達前的本機操作 | 舊程式結果 | 本輪修正後 |
|---|---|---|
| 已保存等待結束確認 | 舊 active 回應再次啟動定位，啟動次數 1（預期 0） | 保留 completionPending，定位不重啟，畫面發布最新狀態 |
| 同一帳號已啟動新勤務 | 舊 ended 回應清掉新勤務 | 舊回應失效，重新核對新勤務；不清除、不停止新勤務 |
| 同一帳號已啟動新勤務 | 舊查詢錯誤停止新勤務並拋出過時錯誤 | 不把過時失敗套用到新勤務，重新核對並發布最新狀態 |

修正位於 account-lifecycle.ts 與 App.tsx：本機勤務的開始、等待結束與完成清除均更新獨立狀態版本；刷新流程在查詢返回、排入原生操作、以及發布畫面前檢查同一版本。版本改變即重新讀取本機狀態，不套用過時查詢。網路查詢不占住原生操作序列，避免等待網路時阻塞結束或登出。

完成後清除本機勤務也改經同一序列，核對勤務編號、駕駛與登入狀態，防止延遲清除刪到別筆勤務。若清除的磁碟寫入失敗，錯誤回報且保留勤務，後續可重試。本輪沒有改動密碼政策、依賴版本、資料庫 migration、RLS 或部署流程。
