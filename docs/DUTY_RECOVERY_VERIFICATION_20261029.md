# 2026-10-29 勤務結束回應遺失與恢復驗證

## 問題與修正

前輪驗證定位上傳的回應遺失，本輪改驗勤務結束 PATCH 的回應遺失。發現兩個產品問題：

1. **已結束勤務可能重新定位**：原生命週期只檢查本機勤務的駕駛身分，沒有向伺服器核對狀態。結束請求已提交、但手機未收到回應，或管理端已結束勤務時，App 重開會重新啟動定位。新增回歸在舊碼重現啟動次數 1（預期 0），查詢失敗的防護亦未成立。影響為勤務結束後仍可能收集定位，以及產生無法通過 active-session RLS 的待傳點。
2. **同一畫面重試會重寫結束時間**：原結束更新只依 session_id，重試已成功但遺失回應的請求時，仍可覆寫 ended_at。改為只更新符合勤務、駕駛及 active 狀態的資料；若沒有更新列，須獨立讀到該勤務 ended 才視為完成。查詢失敗、資料不可見或仍 active 均不當作成功。

修正涵蓋 App、account-lifecycle、background-location、duty-completion、sync 與勤務型別：

- 補傳完成後、送出結束請求前，先將 completionPending 寫入既有加密勤務儲存；寫入失敗不送結束請求。
- 等待結束確認的勤務，重開仍保持停止；原生無畫面回呼同樣不再產生定位點。介面明示「定位已停止，等待勤務結束確認」。
- 恢復勤務前，按 session_id 與 driver_id 核對伺服器狀態；ended／不可見時停止定位並移除本機勤務，不刪既有待傳佇列。查詢失敗則停止定位、保留本機勤務與資料，提示恢復網路後重開。
- 本機結束意圖與登出共用序列，延遲查詢不能恢復或清除較新的登入勤務。結束重試保留原始結束時間。

本輪基於修正分支 35dda7d03bd460d4747f0d77720fb4078fa170e2。沒有修改密碼政策、資料庫 migration、RLS、依賴版本或部署工作流程；只操作隔離合成資料。
