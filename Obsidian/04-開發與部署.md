## 本機預覽

V1 頁面沒有編譯步驟，可從儲存庫根目錄啟動靜態檔案伺服器，再開啟：

`/system/index.html`

V2 為 Next.js 靜態匯出，開發預覽使用 `npm run dev:v2`；正式產物使用
`npm run build:pages` 建立於 `_site/`。

## 修改原則

- 維持既有繁體中文介面與視覺風格。
- 日期使用 `YYYY-MM-DD`，時間使用 `YYYY-MM-DD HH:mm`。
- 樓層名稱可能同時存在 `B1` 與 `B1F`，需先正規化。
- 新頁面需補齊導覽列、登入檢查、Supabase 初始化與跨頁連結。
- 不可刪除 `system/plans/` 圖資。
- `theme.js` 共用導覽的舊連結清理邏輯若只比對 href 檔名，遇到「不同用途但剛好連到同一個檔案」的頁面專屬連結會被誤刪（2026-08-04 踩過，`guardpatrol3d.html` 的「巡檢稽核總覽」曾被誤判成舊版「駐衛警巡檢」重複連結而消失）；新增清理規則時務必連結文字也一併檢查。
- 固定定位（`position:fixed`）搭配寫死像素偏移量（如 `top:62px`）的版面，一旦上方元素高度會變動（例如導覽列改成自動換行），要改用 CSS 變數＋ JS 量測實際高度同步，不能繼續假設固定高度。

## 驗證

- 檢查修改頁面的 inline JavaScript 語法。
- 測試登入保護、資料讀寫與錯誤訊息。
- 涉及 SQL 時確認舊環境也能套用。
- 部署後以版本查詢參數避開 CDN 快取確認結果。

來源簽章、全站掃描與 GitHub Pages 發布；Edge Function 只在相關檔案變更時由獨立流程部署。

### 2026-08-26｜資料庫備份自動化（執行層）

> 治理層——核准流程、責任分工、RPO／RTO 目標與驗收證據表——見 [[07-資料庫備份與復原流程]]。本節只記實作。

#### 關鍵發現：Free 方案不必升級也能自動備份

`07` 原本假設 Free 只能靠人工 `pg_dump`，需要資料庫密碼與 Docker（本機三樣都沒有，`supabase db dump` 因缺 Docker 直接失敗）。實際上 **Management API 的 `/database/query` 用既有的 `SUPABASE_ACCESS_TOKEN` 就能唯讀匯出**，不需資料庫密碼、不需 Docker，且可自動化。RPO 因此從「每週人工」變成「每日自動」。

盤點現況：Free 方案、無自動備份、無 PITR；`public` schema 67 張表約 11,450 筆／20 MB；Storage 五個 bucket 約 13 MB。Schema 本身有版控可重建，**真正沒有第二份的是資料**。`trg_prevent_removal` 只擋得住 DELETE 與 TRUNCATE，擋不住寫錯條件的 UPDATE。

#### 實作

- `tools/database-backup.mjs`：逐表分頁以 `row_to_json` 匯出成 NDJSON，型別轉換交給 PostgreSQL；一併下載 Storage 附件。service_role key 只在記憶體停留，不寫檔也不列印
- `tools/database-backup-verify.mjs`：比對 sha256 與行數，對不上就讓流程失敗
- `tools/database-restore.mjs`：**不接任何 workflow，只能人工執行**。預設演練，要 `--execute` 且 `--confirm` 對得上專案 ref 才寫入；一律 upsert 或 insert-missing，**永不刪除**，符合正式資料只能追加／更新／停用
- `tools/database-backup-consistency-check.mjs`：23 項離線測試，已接進 `npm test`
- `.github/workflows/database-backup.yml`：每天台北時間凌晨 2 點，AES256 加密後存 artifact（保留 90 天）

#### 為什麼加密是強制的

**本 repo 是 public，artifact 任何人都下載得到**，而備份含全公司人員個資與巡檢／報修紀錄。缺少 `BACKUP_PASSPHRASE` 時流程直接中止，不會退而求其次產生未加密的檔案；上傳前還會確認產物確實解不開成 tar。這與 `07` 第 3 節「不要使用 repository 儲存」有張力，取捨已寫在該處。
